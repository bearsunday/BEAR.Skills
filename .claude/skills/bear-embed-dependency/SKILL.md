# 宣言でキャッシュの依存を集める

bear/query-repository 1.21 以降（bearsunday/BEAR.QueryRepository#294）と bear/resource 1.36 以降が前提。それより前の BQR では、キャッシュの属性のない子は依存にならず、キャッシュの属性のないリソースへの書き込みは何も消さない。

## ルール

1. **使ったものに依存する。** ページの `onGet()` が読む子（ページを保存するときに body を持っている子）は、キャッシュの属性があってもなくても、ページの依存になる。
2. **テンプレートが出力する子は「穴」。** ページは、子の場所を穴として空けたテンプレートとして保存される。子が変わると、穴だけを描き直し、ページの本体は作り直さない。
3. **使わない子は、依存にならない。** 埋め込んだだけで、読みも出力もしない子は、どこにもキーを渡さない。使わないなら、依存しなくてよい。
4. **書き込めば、自分のキーが消える。** `onPut` / `onPost` / `onPatch` / `onDelete` は、そのリソース自身のキーを消す（キャッシュの属性がなくても）。データの持ち主のリソースに書き込めば、そのデータを使うページが消える。
5. **データで決まる依存は `#[DependsOn]`。** 依存先がデータを読んで初めて決まるとき（行が指す分類など）だけ、行のクラスか `onGet()` に宣言する。
6. **アプリ全体のものは `AppSurrogateKeyModule`。** デプロイや、サイト全体の設定の変更のように、全部を作り直すものは、ページごとの依存にせず、アプリのキー（`__all` など）を purge する。

`resource()` や `$this->resource->get()` で取りに行ったものは、宣言されていないので、ライブラリは追わない。

## 手順

### 1. 手作りのキーと、取りに行く経路を洗い出す

```bash
grep -rn "SURROGATE_KEY\|SurrogateKey\|invalidateTags\|fromAssoc" src
grep -rn "resource('\(app\|page\)://\|resource->get(" src var/qiq var/templates
```

キーごとに、どのデータの変化を表すか、そのデータを誰が書くか（リソース、管理画面、バッチ、外部）を表にする。

### 2. 置き換える

| 今の形 | 置き換え |
|---|---|
| ページの共通部分を、テンプレートが `resource()` で取りに行く | レイアウト属性（`AbstractResourceLayout` を継承し、`EMBED` 定数に rel => src）でページに埋め込み、テンプレートは `{{= $this->rel }}` で出力する |
| 埋め込んだ子のキーを、親に手で足す | 消す。ライブラリが集める |
| データを持つリソースの変更を、キーで手で消す | そのデータの持ち主のリソースに書き込む。書き込みが自分のキーを消す |
| 行が指す別のリソースへの依存を、手でキーにする | 行のクラスに `#[DependsOn(uri: 'app://self/x?id={xId}')]` |
| 全ページ共通のキー（`__all`、サイトの設定） | `AppSurrogateKeyModule` と、運用での purge |
| 依存のためだけに `#[Embed]` して読む | しない。使わないなら依存しない |

### 3. `$this->body` を丸ごと代入しない

`#[Embed]` とレイアウト属性は、`onGet()` の前に、埋め込むリクエストを `$this->body[rel]` に入れる。`onGet()` で `$this->body = [...]` と丸ごと代入すると消える。`$this->body += [...]` か `$this->body['x'] = ...` を使う。`+=` は既にあるキーを上書きしないので、子と同じ名前のキーを使わない。

### 4. テンプレートのフォールバックを消す

`{{= $this->header ?? $this->resource('...') }}` の `??` の右側は、レイアウト属性を付け忘れたページで、黙って取りに行く道になる。レイアウト属性を全ページに付けてから消す。Qiq は、ない変数を警告（`Undefined property`）と空文字にするだけで、付け忘れを止めない。

### 5. 確かめる

- **HTML**：同じ seed で、変更前と変更後のページを描き、バイト単位で比べる。SQL の `RAND()` を使うページは、セッションの乱数の種を固定する。
- **書き込み**：データの書き込み（トランザクションの中でロールバック）のあとに、それを表示するページがキャッシュから消えることを、`Age` ヘッダーか保存の有無で見る。
- **使っている値**：設定などの値を固有の文字列に書き換えて描き、どのページの出力に出るかを見る。出るのに、書き込みで消えないページがあれば、宣言されていない取得が残っている。
- **保存されたテンプレート**：ドーナツのテンプレートを取り出し、穴（`[le2:...]`）が埋め込んだ部品の数だけあるかを見る。テンプレートに焼き込まれた部品は、取りに行く経路が残っている。
- **qr-graph**：`qr-graph snapshot` の差分で、依存の線がどう変わったかを見る。

## 気をつけること

- 書き込みのメソッドは、自分の ResourceObject を返す。別のリソースを返すときも、自分のキーは書き込み先のリソースから取られる。
- 書き込みが、ほかのリソースのデータを直接書き換えるなら、`#[Purge]` で消す URI を宣言する。
- `#[HttpCache]` だけのページは、ライブラリが保存せず、キーも付けない。CDN の TTL だけで切れる。
